A dashboard for your self-hosted GitHub Actions runner.

cothon shows every job your runner picks up, across all your repos: live CPU and memory, the queue, rerun and cancel, and start or stop for the runner itself.

$go install github.com/aymenkrifa/cothon/cmd/cothon@latest

Then cothon web. Linux and macOS, MIT · Source on GitHub

cothon reads the runner's own logs. No admin rights, no webhooks, nothing to host: a job shows up the moment it starts, even offline.

01

What it does

Every job, every repo

Grouped by repository and run, or as one list. Filters live in the URL, so any view is a bookmark.

Live CPU and memory

The running job's CPU, memory and processes as they happen. Finished jobs keep their average and peak.

The queue

Jobs waiting for this runner, asked from GitHub for the repos it worked on recently.

Rerun and cancel

Rerun a job, rerun the failed ones, or cancel a run without leaving the list.

Runner control

Start it detached, stop or restart it after the current job, follow its logs, start it at login.

Private by default

Localhost only, behind one-time sign-in links. Only the queue and your actions talk to GitHub.

02

Start in three commands

1

Install

One Go command. cothon update keeps it current.

$ go install github.com/aymenkrifa/cothon/cmd/cothon@latest
2

Open it

The server starts in the background and stops after the last tab closes.

$ cothon web
3

Manage the runner

No more run.sh in a terminal you can't close. Stop waits for the current job.

$ cothon runner start   # detached
$ cothon runner logs -f
$ cothon runner stop    # after the job
$ cothon runner enable  # at login
03

What you need

Watching jobs needs only the runner's logs. The GitHub CLI is for the actions that talk to GitHub.

  • Linux or macOSThe machine your runner runs on.
  • A self-hosted runnerInstalled from GitHub's tarball, in ~/actions-runner or wherever runner_dir points.
  • Go 1.24+To install and update cothon.
  • GitHub CLIOptional. Logged in, for rerun, cancel and the queue.
